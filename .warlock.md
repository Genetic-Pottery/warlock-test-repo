# warlock-test-repo

Root of the warlock test repository: a shell-script test suite covering warlock's pact/unpact, scope, check, and stale/fresh ledger commands, alongside sample source directories (engine, services, monolith, legacy, pipeline, web, tools, infra, data, docs) used as fixtures for those tests.

## Files

- `check.sh` (4.6 KB) — Bash test script: runs `warlock pact .` then checks each directory's .warlock.md for expected symbols and existence; not application code.
- `incremental.sh` (6.1 KB) — Test script asserting warlock refresh touches only changed/added/deleted file lines in engine/core/.warlock.md, leaving siblings byte-identical.
- `scopes.sh` (8.1 KB) — Bash test suite exercising warlock scope add/remove, pact/unpact, check --json, and the gate hook's permissionDecision across nested scopes and sigils.
- `surfaces.sh` (8.3 KB) — Shell test script exercising warlock's `stale`/`fresh` ledger commands and plain/--json output against .warlock/pacts.toml, checking partitioning, unpact, and manifest round-trip.

## Directories

- `data/` — Generated JSON inventory dataset, its SQL schema, and an unrelated binary logo asset.
- `docs/` — Empty, unpopulated directory with no files or subdirectories.
- `engine/` — Core submodule supplying foundational ledger types, hashing, and balance utilities.
- `infra/` — Terraform config provisioning the artifacts S3 bucket.
- `legacy/` — C frame codec (Frame, encode, CODEC_VERSION) plus a stub C++ decoder class.
- `monolith/` — Flat Go/Python/TypeScript domain modules (ledger, invoice, tenant, etc.) with duplicated Apply/Resolve/Compact worker types and a shared schema.sql.
- `pipeline/` — Pipeline.Stage module summing items via run/1, plus its test suite.
- `services/` — API server boot/routing logic and billing domain types (Invoice, Ledger, Payment, Refund) across Java, Kotlin, C#, Swift.
- `tools/` — Build/deploy scripts and inventory/report utilities (Shelf, Report, build_report) with specs/tests.
- `web/` — Stubbed fetchCart API client, legacy retry utility, and the Cart component.
