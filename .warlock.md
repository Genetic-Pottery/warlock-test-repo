# warlock-test-repo

Test repository for warlock, holding shell test scripts that exercise pact/scope/surface/incremental behavior against a fixture codebase spanning multiple languages and service directories.

## Files

- `check.sh` (6.5 KB) — Bash test harness that re-pacts the fixture repo and asserts expected symbols appear in each directory's .warlock.md.
- `incremental.sh` (7.7 KB) — Shell test script exercising warlock's incremental refresh: verifies changed/new/deleted files and .warlockignore updates .warlock.md without disturbing unrelated lines.
- `run.sh` (2.6 KB) — Test runner: runs surfaces.sh and scopes.sh by default, or with --paid also check.sh and incremental.sh, requiring .warlock/pacts.toml unless --paid.
- `scopes.sh` (8.1 KB) — Shell test suite exercising warlock scope/pact/check/gate behavior across nested directories, sigils, and manifest mutations against a sandboxed pacts.toml.
- `surfaces.sh` (15.8 KB) — Shell test script exercising warlock stale/fresh/push/unpact against a sandboxed pacts.toml, checking exit codes, JSON output, and manifest idempotence.

## Directories

- `data/` — Inventory data store: JSON records, SQL schema, and a binary logo asset; go here for inventory table or data-file questions.
- `docs/` — Empty documentation directory with no files or subdirectories.
- `engine/` — Holds core ledger primitives (balance checks, hashing, entry posting/reversal); go here for ledger entry or hash questions.
- `infra/` — Terraform config provisioning an S3 artifacts bucket; go here for AWS infrastructure questions.
- `legacy/` — C frame encoder/header paired with a C++ decoder validating frame counts; go here for frame codec questions.
- `monolith/` — Flat Go/Python/TypeScript billing-and-ops modules (ledger, invoice, quota, payout, refund, shipment, tax, usage, session, etc.) with near-duplicated store/repo/projection/gateway patterns plus shared SQL schema.
- `pipeline/` — Elixir Pipeline.Stage module summing items, with its ExUnit test; go here for item-summing questions.
- `services/` — API entry point/boot sequence and billing entities for invoices, ledgers, payments, and refunds.
- `tools/` — No own files; holds a scripts subdirectory for deploy, inventory modeling, and report generation.
- `web/` — Root-level web source utilities: a cart-fetching API stub and a legacy retry helper.
