# warlock-test-repo

Root of the warlock test fixture repository, holding shell test suites that exercise warlock's CLI (pact/unpact, scopes, check --json, stale/fresh/push, incremental refresh) against the sample source directories below.

## Files

- `check.sh` (6.2 KB) — Bash test script re-pacting the fixture repo with warlock, then checking each directory's .warlock.md for required symbols
- `incremental.sh` (7.7 KB) — Test script verifying warlock's incremental refresh of engine/core/.warlock.md on file edits, additions, deletions, and .warlockignore handling.
- `scopes.sh` (8.1 KB) — Bash test suite exercising warlock scope add/remove, pact/unpact, check --json, and the gate hook's permissionDecision across nested scopes and sigils.
- `surfaces.sh` (15.8 KB) — Shell test suite exercising warlock's stale/fresh/push/unpact CLI surfaces against the pacts.toml manifest and briefs, restoring state on exit via trap cleanup.

## Directories

- `data/` — Inventory data assets: generated JSON dataset, its SQL schema, and a binary logo blob.
- `docs/` — Empty, unpopulated directory.
- `engine/` — Holds core/, with ledger accounting, balance-check, and hashing primitives.
- `infra/` — Terraform config provisioning the artifacts S3 bucket.
- `legacy/` — C frame codec (encode, Frame struct) plus a stub, non-functional C++ decoder class.
- `monolith/` — Flat pile of duplicate-ridden Go/Python/TypeScript domain modules (ledger, invoice, tenant, etc.) sharing schema.sql and clock.ts; go here for repetitive Apply/Resolve/Compact/etc worker-type questions.
- `pipeline/` — Elixir Pipeline.Stage module summing items, with its test suite.
- `services/` — Backend subsystems: api/ server boot logic and billing/ domain types across several languages.
- `tools/` — Build/deploy tooling plus inventory and report utilities under scripts/, with specs/tests.
- `web/` — Web project root; src/ holds the stubbed cart API client, legacy retry utility, and Cart component.
