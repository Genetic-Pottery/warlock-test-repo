# warlock-test-repo

Root of the warlock test repository: shell test scripts exercising the warlock CLI's pact, scope, check, incremental refresh, and surface (stale/fresh/push/unpact) behaviors, run via run.sh against a sandboxed pacts.toml.

## Files

- `check.sh` (6.6 KB) — Shell test harness that runs `warlock pact`, restores fixture scopes, then checks generated .warlock.md files for expected symbols and directory coverage
- `incremental.sh` (7.7 KB) — Shell test script exercising warlock's incremental refresh: verifies changed/new/deleted files and .warlockignore updates .warlock.md without disturbing unrelated lines.
- `run.sh` (2.6 KB) — Test runner checking warlock binary and .warlock/pacts.toml, then running surfaces.sh and scopes.sh, with check.sh/incremental.sh only under --paid
- `scopes.sh` (8.1 KB) — Shell test suite exercising warlock scope/pact/check/gate behavior across nested directories, sigils, and manifest mutations against a sandboxed pacts.toml.
- `surfaces.sh` (15.8 KB) — Shell test script exercising warlock stale/fresh/push/unpact against a sandboxed pacts.toml, checking exit codes, JSON output, and manifest idempotence.

## Directories

- `data/` — Inventory data store: a large JSON records file, SQL schema for the inventory table, and a binary logo asset.
- `docs/` — Documentation directory with no listed files or subdirectories.
- `engine/` — Holds core/, implementing ledger primitives (balance checks, hashing, entry posting/reversal).
- `infra/` — Terraform config provisioning an AWS S3 artifacts bucket, with its region variable and bucket_name output.
- `legacy/` — Legacy frame codec: a C Frame struct/encoder with header, and a separate C++ Decoder validating frame counts.
- `monolith/` — Flat Go/Python/TypeScript modules modeling billing/ops entities (ledger, invoice, quota, payout, refund, shipment, tax, usage, etc.) via duplicated store/repo/projection/gateway patterns, plus a shared SQL schema.
- `pipeline/` — Elixir Pipeline.Stage module summing a list of items, with its ExUnit test.
- `services/` — API entry point/boot sequence and billing entities for invoices, ledgers, payments, and refunds.
- `tools/` — Holds scripts/ with a deploy script, Ruby inventory modeling, and Python report generation.
- `web/` — Root-level web source utilities: a cart-fetching API stub and a legacy retry helper, under src/.
