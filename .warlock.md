# warlock-test-repo

Root of warlock-test-repo, a test fixture repository exercising warlock's pact/unpact, scope, check, stale/fresh, and incremental-refresh commands against a deliberately varied multi-language codebase.

## Files

- `check.sh` (4.6 KB) — Bash test script: runs `warlock pact .` then checks each directory's .warlock.md for expected symbols and existence; not application code.
- `incremental.sh` (7.7 KB) — Test script verifying warlock's incremental refresh of engine/core/.warlock.md on file edits, additions, deletions, and .warlockignore handling.
- `scopes.sh` (8.1 KB) — Bash test suite exercising warlock scope add/remove, pact/unpact, check --json, and the gate hook's permissionDecision across nested scopes and sigils.
- `surfaces.sh` (10.4 KB) — Shell test script exercising warlock's `stale`/`fresh`/`unpact` commands against a sandboxed pacts.toml manifest, asserting plain and --json output partition pacted directories consistently.

## Directories

- `data/` — Holds a generated JSON inventory dataset, its SQL schema, and an unrelated binary logo asset; go there for inventory data or schema questions.
- `docs/` — Empty, unpopulated directory with no files or subdirectories.
- `engine/` — Contains core/ with ledger accounting, balance-check, and hashing primitives; go there for accounting or hashing logic.
- `infra/` — Terraform config provisioning the artifacts S3 bucket; go there for infrastructure or bucket provisioning questions.
- `legacy/` — Legacy C frame codec (Frame struct, encode()) plus a stub unimplemented C++ decoder class; go here for legacy codec questions.
- `monolith/` — Flat collection of duplicate-riddled Go/Python/TypeScript domain modules (ledger, invoice, tenant, billing, etc.) sharing Apply/Resolve/Compact/Validate/Project/Reconcile/Emit/Settle worker patterns, schema.sql, and clock.ts; go here for any domain worker or store logic question.
- `pipeline/` — Contains Pipeline.Stage, an Elixir module summing items via run/1, with its test suite.
- `services/` — Groups backend service subsystems: the api/ server boot logic and billing/ domain types across Java, Kotlin, C#, Swift.
- `tools/` — Holds build/deploy tooling plus inventory and report utilities with tests in scripts/.
- `web/` — Web project root with src/ holding the stubbed fetchCart client, legacy retry utility, and Cart component.
