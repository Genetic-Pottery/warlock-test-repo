# monolith

Billing and platform monolith combining Go stores/appliers, Python event projections, and TypeScript gateways for entities like ledger, invoice, tenant, quota, subscription, refund, dispute, payout, shipment, and inventory, backed by a shared SQL schema.

## Structure

- Each Go *.go file's Applyer/Resolveer/etc types call store.Load then store.Save on a matching *Store type via clock() for the Stamp field.
- Each Python *_projection.py / *_repo.py dataclass filters events by a 'kind' string then appends to rows and exposes drain() to flush them.
- Each TypeScript *Gateway.ts class imports Clock from clock.ts and its apply/resolve/etc methods loop calling a private probe() method.
- schema.sql defines one table plus a tenant/stamp index per entity named across the Go stores and Python repos/projections.
- reconcile.go body is truncated in this view; only its opening declarations and imports are shown in full.

## Where to look

- how a single entity's create/read/apply flow works in Go → `ledger.go` `LedgerApplyer`
- database schema and table names for all entities → `schema.sql` `CREATE TABLE ledger`
- shared Clock abstraction used by TypeScript gateways → `clock.ts` `systemClock`
- how Python projections window and drain buffered events → `invoice_projection.py` `drain`
- reconciliation logic and its store-backed appliers → `reconcile.go` `ReconcileApplyer`
- TypeScript gateway pattern for coupons → `couponGateway.ts` `CouponApplyGateway`
