# monolith

A tenant-scoped monolith of near-duplicate Apply/Resolve/Compact/Validate/Project/Reconcile/Emit/Settle wrappers, one set per domain entity (ledger, invoice, tenant, quota, webhook, session, audit, payout, dispute, refund, coupon, fx, shipment, subscription, tax, usage, settlement, retry, export, reconcile), spanning Go store wrappers, Python windowed event-folding dataclasses, and TypeScript clock-probed gateways, all backed by a shared SQL schema.

## Structure

- schema.sql — SQL schema defining 28 near-identical tenant-scoped tables (ledger, invoice, tenant, quota, webhook, session, audit, payout, dispute, refund, etc.), each with id, tenant, amount, stamp columns and a tenant/stamp index.
- clock.ts — Defines the Clock interface with now(), and systemClock, a Clock implementation backed by real Date.
- couponGateway.ts — probes coupons via CouponXOptions{attempts,window} against a Clock.
- disputeGateway.ts — repeated gateway classes each with matching Options interface and probe-based async method.
- entitlementGateway.ts — Gateway classes probing via clock-based attempts/window options.
- pricingGateway.ts — gateway classes wrapping Clock probes.
- sessionGateway.ts — Gateway classes probing via clock with attempts/window options.
- settlementGateway.ts — Gateway classes probing SettlementId via a clock-driven attempts/window loop.
- tenantGateway.ts — per-op gateways with matching Options interfaces, each probing via a Clock.
- shardGateway.ts — Gateway classes polling via Clock; duplicate class names redeclared.
- rollupGateway.ts — Defines RollupId and duplicated gateway classes probing an id with attempts/window options via Clock.
- replayGateway.ts — Duplicated ReplayId-keyed gateway classes each with matching Options interface and probe-based counting method.
